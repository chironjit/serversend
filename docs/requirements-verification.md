# Requirement-to-test map

This is the verification index for every section of [implementation plan](implementation-plan.md). It distinguishes tests that exist from later acceptance work. A shared contract test proves serialization or a deterministic rule; it does **not** prove that the server enforces authorization, that files are durable, or that a UI/platform workflow exists. The [feature roadmap](implementation-tasks.md) is the source of current delivery status. Historical chunk references in this index map to features through its historical requirement mapping; they are not the current work order.

Existing test references below are source paths and exported test names. “Planned” names acceptance scenarios, not implemented tests. Before release qualification, replace each planned row with the owning suite, recorded execution evidence and any remaining platform/hardware gate. Every implementation also needs normal, invalid, authorization, boundary and relevant failure/recovery coverage.

### Release onboarding rate-limit regression (2026-11-17)
